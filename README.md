# doc_helper

Внутренняя Django-система для ведения исполнительной документации в строительных проектах.

Проект связывает:
- бизнес-сущности в PostgreSQL
- реальные файлы на диске
- генерацию документов по шаблонам

Основной сценарий работы:
- загружаются паспорта, проекты, приказы и согласования
- на их основе собираются акты и сопроводительные документы
- часть выходных документов конвертируется в PDF

## Основные модули

- `acts_app` — акты, протоколы, сборка итоговых документов
- `passports_app` — паспорта материалов, импорт PDF и архивов
- `projects_app` — проекты и их ревизии
- `directive_app` — приказы, доверенности, основания для подписантов
- `approvals_app` — согласования
- `orgs_app` — организации, люди, НРС
- `documents_app` — сопроводительные документы, титульные листы, наклейки
- `authapp` — кастомный пользователь и авторизация
- `health_app` — служебные health-check сценарии

Неактуальные или локально использовавшиеся части:
- старый `checker_app` удалён из рабочего контура приложения
- отдельные старые management-команды могли использоваться только локально

## Технический стек

- Python
- Django
- PostgreSQL
- `python-docx`
- `openpyxl`
- `Pillow`
- LibreOffice / `soffice` для части PDF-конвертаций

## Как устроено хранение данных

Проект сильно опирается на файловую структуру вне репозитория. Базовая директория задаётся через:

- `DOC_HELPER_BASE_ID_DIR`

Внутри неё ожидаются рабочие каталоги:

- `Паспорта`
- `Проекты`
- `Приказы`
- `Согласования`
- `Акты`
- `Документы`

Это важно: часть бизнес-логики работает не только с БД, но и с физическими файлами в этих папках.

## Локальный запуск

Минимальные требования:
- Python
- PostgreSQL
- заполненный `.env`
- доступная файловая директория `DOC_HELPER_BASE_ID_DIR`

Пример переменных есть в [`.env.example`](C:\my_projects\doc_helper\.env.example).

Базовый сценарий запуска:

```bash
python -m venv venv
venv\Scripts\activate
pip install -r requirements.txt
python manage.py migrate
python manage.py runserver
```

Если нужен полный рабочий контур генерации PDF, на машине должен быть установлен LibreOffice.

## Тесты

Сейчас в проекте есть базовые тесты для `projects_app`.

Запуск:

```bash
python manage.py test projects_app --settings=settings.test_settings
```

Тестовые настройки используют отдельный SQLite-контур и не требуют боевой PostgreSQL-базы.

## С чего начать новому разработчику

1. Прочитать [ARCHITECTURE.md](C:\my_projects\doc_helper\ARCHITECTURE.md)
2. Прочитать [CONTRIBUTING.md](C:\my_projects\doc_helper\CONTRIBUTING.md)
3. Поднять локальное окружение с тестовым storage-путём
4. Начинать изменения с `projects_app`, `acts_app`, `passports_app` и `documents_app`

## Что важно понимать заранее

- это не “чистый” CRUD-проект, а система вокруг документов и файлового хранилища
- часть поведения завязана на шаблоны DOCX/XLSX и файловую структуру
- при изменениях нужно смотреть и на БД, и на файловые операции, и на генерацию документов
