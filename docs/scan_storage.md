# Сканы ИД в S3

В карточке комплекта можно загрузить несколько PDF/архивов (ZIP, 7Z, RAR,
TAR, GZ), до 5 ГиБ каждый. Архивы хранятся как есть, без распаковки.
Кнопка доступна с правом `change_documentbatch`, скачивание — с
`view_documentbatch`. Действуют общие права на комплекты приложения.

Браузер отправляет части по 16 МиБ напрямую в приватный S3 по подписанным
ссылкам. Секретные ключи остаются на сервере. Django принимает только метаданные,
проверяет фактические размеры частей и завершает загрузку. Временная ссылка на
скачивание действует 5 минут. Лимиты тела запроса nginx увеличивать не нужно.

## Настройка перед использованием

По умолчанию используются уже заданные `S3_BACKUP_*` реквизиты и бакет,
с отдельным префиксом `id-scans/`. Флаг `S3_BACKUP_ENABLED` не управляет сканами.
При необходимости отдельного бакета можно задать `S3_SCAN_BUCKET`,
`S3_SCAN_ENDPOINT_URL`, `S3_SCAN_REGION`, `S3_SCAN_ACCESS_KEY_ID`,
`S3_SCAN_SECRET_ACCESS_KEY` (пустые значения наследуют соответствующие BACKUP).
Текущий deploy workflow записывает только BACKUP-переменные: для отдельного
бакета потребуется также добавить SCAN-переменные в управление окружением деплоя.

1. Применить миграции и собрать статику обычным деплоем.
2. В настройках CORS бакета добавить правило (существующие правила сохранить):

```json
[
  {
    "AllowedOrigins": ["https://doc-helper.pro"],
    "AllowedMethods": ["PUT"],
    "AllowedHeaders": ["*"],
    "MaxAgeSeconds": 3600
  }
]
```

Origin должен точно совпадать с адресом приложения. Для локальной проверки
добавьте конкретный локальный origin. Открывать публичный доступ к бакету не нужно.
ETag браузер не читает: список частей и их размеры проверяет сервер через ListParts.

3. Учётной записи S3 нужны операции создания/завершения multipart upload,
UploadPart, ListParts, AbortMultipartUpload, GetObject/HeadObject, DeleteObject
на `id-scans/*` (AWS IAM: `s3:PutObject`, `s3:GetObject`, `s3:DeleteObject`,
`s3:ListMultipartUploadParts`, `s3:AbortMultipartUpload`).
4. Добавить lifecycle-правило AbortIncompleteMultipartUpload через 1 день
для префикса `id-scans/`. Не включать удаление завершённых объектов по возрасту.
Это очищает части, оставшиеся после закрытия вкладки/аварии. Правило не следует
применять заменой всех существующих lifecycle-правил бакета.

## Поведение при ошибках

Часть автоматически повторяется до трёх попыток. Есть прогресс и отмена.
Не закрывайте страницу до завершения. Возобновление после закрытия вкладки
не реализовано: удалите незавершённую запись и загрузите файл заново.
Незавершённые записи видны в карточке, удалить их может автор или суперпользователь.
Успешно загруженные сканы может удалить пользователь с правом изменения комплекта.
При ошибке удаления S3 запись сохраняется для повторной попытки.
Удаление комплекта блокируется, пока у него есть сканы/незавершённые загрузки.

Сканы не входят в локальные ZIP-бэкапы: в бэкап БД входят только ссылки и метаданные.
При восстановлении необходимо сохранить доступ к исходному S3-бакету и его объектам.
При включённом versioning удаление создаёт delete marker; старые версии регулируются
политикой бакета. Не меняйте endpoint/бакет без переноса существующих объектов.

## Проверка после развёртывания

Загрузить небольшой PDF/ZIP, скачать и сравнить содержимое; проверить отмену.
Затем загрузить архив примерно 1,5 ГБ и сравнить SHA-256 исходного и скачанного файла.
Убедиться, что в сетевой панели браузера PUT идут непосредственно в S3.
Локальные автоматические тесты подменяют S3 и не подтверждают настройки живого бакета.

Протокол: https://docs.aws.amazon.com/AmazonS3/latest/userguide/mpuoverview.html

## Поделиться сканами

Кнопка Share в списке комплектов доступна с правом `change_documentbatch`.
Она создаёт отдельную случайную ссылку на публичную страницу «Doc-helper облако»
на 7 дней и копирует её в буфер обмена. Если браузер запрещает копирование,
появляется поле с выделенной ссылкой для ручного копирования.

Получателю не нужен аккаунт: доступ имеет любой обладатель ссылки.
В ссылку включаются только завершённые сканы на момент создания и краткий снимок
комплекта (название, период, шифры проектов, число актов). Внутренние комментарии
и данные сотрудников не публикуются. Новые сканы автоматически не добавляются.
Архивы не распаковываются: описание основано на составе комплекта, не на проверке
содержимого архива. Если файлов несколько, у каждого своя кнопка скачивания.

Срок проверяется при открытии страницы и при каждом скачивании. S3-ссылка выдаётся
на час, но не дольше оставшегося срока общего доступа. Уже начатая передача может
завершиться после истечения срока. Удалённые сканы перестают выдаваться.
Публичные страницы не кэшируются и помечены noindex; бакет остаётся приватным.
Для развёртывания требуется миграция `0012_batchscanshare` и сборка статики.
